O(1)

⚡ Teletransporte Direto

▾

🔮 Metáfora: O Mago Mestre guardou cada poção em um compartimento numerado da mochila mágica. Quando ele quer a poção da posição 0, ele não precisa vasculhar nada — a mão dele vai direto ao compartimento certo. Isso funciona igual se a mochila tiver 5 itens ou 5 milhões: o gesto é o mesmo e o tempo é o mesmo. O tamanho do baú não muda nada.

⚙️ Técnica: Acessar lista[0] em Python é uma operação de tempo constante. A lista guarda seus elementos em posições conhecidas, então o Python consegue chegar direto ao elemento pedido, sem percorrer os outros. O tempo de execução não depende de n — o número de itens da lista. Por isso dizemos O(1): o custo é o mesmo para qualquer tamanho de entrada. Dobrar, triplicar ou multiplicar n por mil não altera o tempo dessa operação. 

def invocar_primeiro_feitico(feiticos: list):
    """
    Complexidade: O(1)
    Acessa diretamente o primeiro elemento da lista.
    """

    if not feiticos:
        return None

    return feiticos[0]


# Teste
feiticos = [
    "Bola de Fogo",
    "Teletransporte",
    "Escudo Arcano",
    "Raio de Gelo"
]

print(invocar_primeiro_feitico(feiticos))
O(log n)

🔍 Oráculo Binário

▾

🔮 Metáfora: O Oráculo tem um tomo gigante com runas em ordem crescente, uma por página. Em vez de folhear página por página, ele abre o tomo exatamente no meio. Compara a runa do meio com a que procura: se for menor, sabe que o alvo só pode estar na metade direita; se for maior, só pode estar na esquerda. Ele descarta a metade inútil e repete o processo no que sobrou. A cada consulta, o problema encolhe pela metade.

⚙️ Técnica: Essa é a busca binária. Se a lista tem n elementos, quantas vezes conseguimos dividir por 2 até sobrar 1? Exatamente log₂(n). Para n = 1.000.000, bastam cerca de 20 comparações. Para n = 2.000.000, apenas 21 — ou seja, dobrar o tamanho da entrada adiciona uma única comparação. Por isso O(log n) é considerado muito eficiente mesmo para listas grandes, desde que estejam ordenadas. 

def buscar_runa(runas: list, alvo: int):
    """
    Complexidade: O(log n)
    A lista deve estar ordenada.
    A cada etapa, metade das possibilidades é descartada.
    """

    inicio = 0
    fim = len(runas) - 1

    while inicio <= fim:
        meio = (inicio + fim) // 2

        if runas[meio] == alvo:
            return meio

        if runas[meio] < alvo:
            inicio = meio + 1
        else:
            fim = meio - 1

    return -1


# Teste
runas = [10, 20, 30, 40, 50, 60, 70, 80, 90]

posicao = buscar_runa(runas, 70)

print(f"Runa encontrada na posição: {posicao}")
O(n)

🛡️ Ronda das Sentinelas

▾

🔮 Metáfora: A sentinela da muralha recebe uma fila de viajantes desordenados e precisa conferir o passaporte de cada um, um por um. Não tem como pular ninguém: cada viajante pode ser o procurado. Se chegarem 10 viajantes, ela faz 10 verificações. Se chegarem 100, faz 100. Se a fila dobrar, ela gasta exatamente o dobro do tempo.

⚙️ Técnica: Isso é uma varredura linear — percorrer todos os n elementos uma única vez com um for. Cada elemento é visitado exatamente uma vez, então o custo cresce proporcionalmente ao tamanho da entrada. Se n dobra, o tempo dobra; se triplica, o tempo triplica. É o comportamento de operações como procurar um item em uma lista não-ordenada, somar todos os valores de uma lista ou contar ocorrências. O(n) é considerado eficiente — é o mínimo que se espera quando é preciso olhar cada elemento. 

def procurar_pergaminho(pergaminhos: list, procurado: str):
    """
    Complexidade: O(n)
    Percorre os elementos até encontrar o pergaminho procurado.
    No pior caso, percorre toda a lista.
    """

    for indice, pergaminho in enumerate(pergaminhos):
        if pergaminho == procurado:
            return indice

    return -1


# Teste
pergaminhos = [
    "Pergaminho de Fogo",
    "Pergaminho de Gelo",
    "Pergaminho de Cura",
    "Pergaminho de Sombra",
    "Pergaminho de Luz"
]

posicao = procurar_pergaminho(
    pergaminhos,
    "Pergaminho de Cura"
)

print(f"Pergaminho encontrado na posição: {posicao}")
O(n log n)

📚 Grande Biblioteca

▾

🔮 Metáfora: O Arquimago precisa organizar uma estante com milhares de grimórios fora de ordem. Ele não tenta ordenar tudo de uma vez. Em vez disso, divide a estante ao meio, depois cada metade ao meio de novo, e assim por diante — até cada pilha ter apenas um livro. Depois, começa o trabalho inverso: junta duas pilhas pequenas em uma pilha ordenada, e vai juntando essas pilhas maiores até formar a estante inteira em ordem. Em cada junção, ele compara livro por livro e coloca sempre o menor na frente.

⚙️ Técnica: Essa é a ideia da divisão e conquista aplicada à ordenação. A parte de dividir cria log₂(n) níveis de profundidade, porque cada nível corta a lista pela metade. Em cada nível, o algoritmo precisa percorrer e juntar todos os n elementos uma vez. Multiplicando: n × log₂(n) operações no total. Para n = 1.000.000, isso dá cerca de 20 milhões de operações — muito menos do que o 1 trilhão que uma ordenação com laços aninhados (O(n²)) exigiria. Por isso O(n log n) é o padrão dos algoritmos de ordenação eficientes. 

def merge_sort(monstros: list) -> list:
    """
    Complexidade: O(n log n)
    Ordena os monstros pelo nível de perigo usando Merge Sort.
    """

    if len(monstros) <= 1:
        return monstros.copy()

    resultado = monstros.copy()
    auxiliar = [None] * len(monstros)

    def dividir_e_mesclar(inicio: int, fim: int):
        if inicio >= fim:
            return

        meio = (inicio + fim) // 2

        dividir_e_mesclar(inicio, meio)
        dividir_e_mesclar(meio + 1, fim)

        i = inicio
        j = meio + 1
        k = inicio

        # Mescla as duas partes ordenadas.
        while i <= meio and j <= fim:
            if resultado[i]["nivel"] <= resultado[j]["nivel"]:
                auxiliar[k] = resultado[i]
                i += 1
            else:
                auxiliar[k] = resultado[j]
                j += 1

            k += 1

        # Copia os elementos restantes da metade esquerda.
        while i <= meio:
            auxiliar[k] = resultado[i]
            i += 1
            k += 1

        # Copia os elementos restantes da metade direita.
        while j <= fim:
            auxiliar[k] = resultado[j]
            j += 1
            k += 1

        # Atualiza a parte ordenada.
        resultado[inicio:fim + 1] = auxiliar[inicio:fim + 1]

    dividir_e_mesclar(0, len(resultado) - 1)

    return resultado


# Teste
monstros = [
    {"nome": "Dragão", "nivel": 100},
    {"nome": "Goblin", "nivel": 10},
    {"nome": "Orc", "nivel": 35},
    {"nome": "Lich", "nivel": 80},
    {"nome": "Slime", "nivel": 5}
]

monstros_ordenados = merge_sort(monstros)

for monstro in monstros_ordenados:
    print(f"{monstro['nome']}: nível {monstro['nivel']}")
O(n²)

⚔️ Duelo dos Aprendizes

▾

🔮 Metáfora: No torneio da Guilda, o Mestre decide que cada aprendiz precisa duelar contra todos os outros, uma única vez, para medir seu poder. Com 10 aprendizes, surgem 45 duelos. Com 20 aprendizes, 190 duelos — quase 4 vezes mais. Com 100 aprendizes, quase 5.000 duelos. O número cresce muito mais rápido do que o número de participantes, porque cada novo aprendiz precisa duelar contra todos os que já estavam lá.

⚙️ Técnica: Isso é o clássico laço aninhado: um for dentro de outro for, cada um percorrendo n elementos, gera n × n = n² iterações. Dobrar o valor de n quadruplica o tempo (2² = 4). Triplicar multiplica por 9 (3² = 9). Algoritmos assim são viáveis só para entradas pequenas — para n = 10.000, já temos 100 milhões de operações. É o custo típico de algoritmos ingênuos de ordenação e de qualquer comparação "par a par" entre elementos. 

def duelos_aprendizes(aprendizes: list):
    """
    Complexidade: O(n²)
    Cada aprendiz enfrenta todos os outros uma única vez.
    """

    duelos = []

    for i in range(len(aprendizes)):
        for j in range(i + 1, len(aprendizes)):
            duelos.append((aprendizes[i], aprendizes[j]))

    return duelos


# Teste
aprendizes = [
    "Arwen",
    "Merlin",
    "Gandalf",
    "Morgana"
]

duelos = duelos_aprendizes(aprendizes)

for aprendiz_1, aprendiz_2 in duelos:
    print(f"{aprendiz_1} vs {aprendiz_2}")
O(2ⁿ)

🧪 Baú das Fórmulas

▾

🔮 Metáfora: O alquimista tem uma bancada com n ingredientes. Para descobrir o elixir lendário, ele precisa testar todas as combinações possíveis: cada ingrediente pode entrar no caldeirão ou ficar de fora. Com 1 ingrediente, há 2 receitas. Com 2, há 4. Com 3, há 8. A cada novo ingrediente, o número de combinações dobra. Com apenas 30 ingredientes, já são mais de 1 bilhão de receitas — impossível testar uma a uma na vida do alquimista.

⚙️ Técnica: Esse é o crescimento exponencial: 2ⁿ. Cada elemento adicionado dobra o trabalho total. Para n = 10, são 1.024 operações (tranquilo). Para n = 30, cerca de 1 bilhão (alguns segundos). Para n = 60, aproximadamente 1,15 × 10¹⁸ operações — mais de 36 anos em um computador que faz 1 bilhão de operações por segundo. É por isso que problemas exponenciais são considerados intratáveis na prática. Exemplos clássicos: gerar todos os subconjuntos de uma lista e calcular Fibonacci por recursão ingênua. 

def fibonacci_magico(n: int) -> int:
    """
    Complexidade: O(2^n)
    Calcula Fibonacci usando recursão ingênua.
    Os mesmos valores são recalculados diversas vezes.
    """

    if n <= 1:
        return n

    return fibonacci_magico(n - 1) + fibonacci_magico(n - 2)


# Teste
n = 10

resultado = fibonacci_magico(n)

print(f"Fibonacci de {n}: {resultado}")
O(n!)

🗺️ Rota do Mensageiro

▾

🔮 Metáfora: O Mensageiro Real precisa entregar cartas em n castelos diferentes e quer descobrir a rota mais curta possível. Ele não conhece atalhos, então decide testar todas as ordens possíveis de visita. Com 3 castelos, existem 6 rotas. Com 4, 24. Com 5, 120. Com 10 castelos, são mais de 3,6 milhões de rotas — e o mensageiro teria que calcular a distância de cada uma. Com 20 castelos, o número é maior do que a quantidade de estrelas da Via Láctea.

⚙️ Técnica: Esse é o crescimento fatorial: n! (produto de 1 até n). Adicionar um castelo multiplica o número de rotas pelo tamanho atual, então o crescimento é ainda mais explosivo que o exponencial. 3! = 6, 5! = 120, 10! = 3.628.800, 20! ≈ 2,4 × 10¹⁸. É a complexidade de qualquer algoritmo que precise gerar todas as permutações de uma lista. Na prática, para n ≥ 15, mesmo os computadores mais rápidos do mundo não conseguem terminar. 

def gerar_permutacoes(castelos: list) -> list:
    """
    Complexidade: O(n!)
    Gera todas as possíveis ordens de visita dos castelos.
    """

    resultado = []
    castelos = castelos.copy()

    def gerar(inicio: int):
        # Quando todos os castelos foram posicionados,
        # uma rota completa foi encontrada.
        if inicio == len(castelos):
            resultado.append(castelos.copy())
            return

        for i in range(inicio, len(castelos)):
            # Coloca um castelo na posição atual.
            castelos[inicio], castelos[i] = (
                castelos[i],
                castelos[inicio]
            )

            gerar(inicio + 1)

            # Desfaz a troca para testar a próxima possibilidade.
            castelos[inicio], castelos[i] = (
                castelos[i],
                castelos[inicio]
            )

    gerar(0)

    return resultado


# Teste
castelos = [
    "Castelo Norte",
    "Castelo Sul",
    "Castelo Leste",
    "Castelo Oeste"
]

rotas = gerar_permutacoes(castelos)

for numero, rota in enumerate(rotas, start=1):
    print(f"Rota {numero}: {' -> '.join(rota)}")
